# 使用说明（运维手册）

面向「拿到这个目录、想直接跑起来」的人。分三步：**装环境 → 准备数据 → 启动网页服务**。

---

## 0. 环境

| 项 | 要求 |
|---|---|
| Python | 3.10+（本项目在 3.13 上实测） |
| 内存 | 约 1.5 GB（6630 块 × 768 维 float32 ≈ 20 MB 向量，其余是模型与分词） |
| 磁盘 | 约 1 GB（本地 bge 模型 + 索引 20 MB + 语料 4 MB + 依赖） |
| GPU | 不需要，CPU 即可运行 |
| 网络 | 仅「生成」一步需要（默认接云端大模型）；检索 / 向量化 / 重排全程离线 |

```bash
cd philo-rag
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
```

配好生成层的密钥（检索本身不需要）：

```bash
cp .env.example .env
# 编辑 .env：DASHSCOPE_API_KEY=sk-你的key
```

服务启动后可在网页直接提问验证生成层；密钥或端点有误时，页面会显示可读错误原因。

国内网络下载 `sentence-transformers` 依赖较慢时，加清华源：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 1. 服务数据

此项目仅提供网页端服务，不包含命令行索引构建、查询或诊断入口。服务启动前需准备好与
`config.yaml` 匹配的 `store/` 索引；当前仓库包含可直接使用的索引数据。索引构建与词典维护
属于离线维护工作，不是网页服务的一部分。

**当前索引概况**（供部署核对）：

```
chunk_count        6630
quote_count        1144
unit_count         327
embedding_backend  sentence_transformer
vector_dim         768
```

索引里同时记录 169 位理论家 / 183 个概念 / 338 个体系单元。
检索回归基线为 `Hit@1 = 96.43% / Hit@3 = 100% / MRR = 0.9821`，由 `pytest` 守护。

## 2. 使用网页服务

从项目根目录启动服务：

```bash
python -m uvicorn philo_rag.server:app --host 127.0.0.1 --port 8000
```

在浏览器打开 <http://127.0.0.1:8000>。服务通过网页提供问答、术语与引文检索、体系浏览、笔记及历史功能；同时提供 JSON API。

打开 http://127.0.0.1:8000 ：两个视图 + 六个可召唤面板 ——**溯源回答 / 连续阅读**，以及 **概念卡 / 检索 / 体系地图 / 笔记 / 历史 / 对比**。

- **溯源回答**：顶部「提问方式」可手动切换，也可留在**自动判定**：

  | 提问方式 | 适用范围 | 示例 |
  |---|---|---|
  | 自动判定 | 由系统按措辞选择下面两者 | 「什么是字头？」「马克思在体系中的位置」 |
  | 点查询 | 问概念/术语**是什么、出自哪里**；8 条召回，数百字 | 「什么是字头？」「大他者是什么意思？」 |
  | 范围查询 | 问主题**在全书的面貌与谱系**；数百块按单元聚合，数千字 | 「马克思在体系中的位置」「谈谈精神分析」 |

  切换后页面即时给出该方式的适用范围与**可点击示例**，点示例直接发问。
  回答与**引用来源**左右分栏：引用来源在固定区域内用 `‹ 3 / 8 ›` **逐条翻页**，
  每条可点「查看上下文」看原文前后段落；按 ← / → 也能翻页。
  范围查询的结果上方会多一张**聚合概览**卡片（命中块数、覆盖单元、共现理论家）。

  同一会话里可以**直接追问**：「继续」「详细点」「为什么」「举个例子」「那黑格尔呢」
  「和康德比呢」。服务端会把追问改写成独立问题，回答卡上方显示「已按上文改写为：…」，
  所以不用重复描述主题；点输入框上方的**最近提问 chips** 可回填，点「新对话」清空上下文。
  会话在服务端内存里，30 分钟无操作即过期（`conversation` 段可调）；过期后再追问会提示
  「对话已过期，请把问题重新完整描述一次」。

- **检索**：把术语与引文合并到同一页，用「检索方式」分段切换，各带适用范围说明：

  | 检索方式 | 回答什么 | 机制 |
  |---|---|---|
  | 术语 / 概念 | 「X 是什么、在哪儿出现」 | 词典卡（归属/别名/定义）+ 精确命中 + 语义补充 |
  | 引文 / 原话 | 「谁说过什么原话、某单元有哪些引文」 | 元数据倒排 + 精确过滤，可枚举可核对 |

  术语卡上有「在引文中检索『X』」按钮，一键切到引文方式。引文方式里「理论家」是
  **相关理论家**（引文所在段落谈到他即命中，召回高）；「说话人」只认有引述标记的精确归因
  （覆盖低但不会张冠李戴）——要「某人的原话」请用说话人。结果统一分页，每页 4 条。

- **分面·体系**：卷级统计、概念与理论家分布、数值单元卡片；点任一卡片转成提问
  （概念 → 点查询「什么是 X？」；理论家 → 范围查询「X 的核心思想是什么？」；单元 → 自动判定）。
  点单元还会打开**单元导览**：子单元、本单元术语（带命中块数）、本单元理论家、
  按阅读顺序分页的原文块列表（每块可「查看上下文」或收藏），以及「用该单元提问」。
- **概念卡**：定义 / 出处 / 单元分布 / 哲学家谱系 / 引文之外，还有**相关概念**
  （与该概念出现在同一块的次数，点击翻到对应概念卡）与**所属主题**（点击直接发起范围查询）；
  顶部两个按钮把术语转成「什么是 X？」与「X 在体系中的位置」。
- **笔记**：在引用卡、概念卡引文、单元导览原文块上点「☆ 收藏」，把该块存进浏览器本地
  （localStorage，不上传、不写库）；可写批注、可回到上下文、可整包导出 Markdown。
- **历史**：本地记录每条回答（问题 / 策略 / 时间 / 引用数）；点条目可**复原当时的回答与引用卡**，
  ★ 收藏，支持本地过滤与导出 JSON（备份）/ Markdown。引用正文不随历史落盘（体积），
  点「展开全文」按需从 `/api/context` 回捞。回答卡右上角的「☆ 收藏本条回答」把整条回答存档。
- **对比**：输入两个概念（如「大他者 / 客体小a」），三栏并排看**定义与归属 / 共现与差异 / 引文**；
  共现 chip 可点开概念卡，某侧词典未收录时只降级该侧。
- **连续阅读**：从体系地图的单元导览点「连续阅读」进入全宽阅读视图，按阅读顺序读完整个单元；
  正文术语自动变可点链接，每块都能收藏 / 看上下文 / 就这段提问；可翻上下单元、调字号，滚动位置会记住。

- **版面为固定视口**：整页锁定高度，只有内容区内部滚动，不会随内容越拉越长。

> 首次提问会有几秒延迟（加载嵌入模型 + 云端生成），之后每次查询都在 1 秒内。
> 范围查询的聚合是纯元数据 + 词法操作，不额外过嵌入模型。
>
> 前端是 `philo_rag/web/` 下的静态文件（HTML + CSS + 原生 JS），**没有构建步骤**；
> 后端只出 JSON API。结构已按层拆开：样式在 `web/css/`（1-tokens → 5-utilities 五层），
> 逻辑在 `web/js/`（00-ns → 80-app 十五个模块），改完刷新即可，无需重新打包。

## 3. 服务接口

问答、术语、引文与体系浏览均可通过网页操作，也可由其他前端调用 JSON API。常用接口见项目根目录 README。

## 4. 生成层：默认云端，可切本地 / 离线

生成层由 `answer.backend` 决定，三选一，**切换不需要重建索引**：

| 后端 | 说明 | 需要什么 |
|---|---|---|
| `api`（默认） | 任意 OpenAI 兼容 `/chat/completions`，默认接阿里云百炼 | 一把 API Key |
| `ollama` | 本地模型，数据不出本机 | 常驻 Ollama 服务 |
| `template` | 离线抽取式：从检索结果挑出相关句子并分组，不做生成 | 无 |

**默认（云端）**——密钥只放 `.env`，`config.yaml` 用 `${VAR}` 引用，可安全提交：

```bash
cp .env.example .env      # 编辑：DASHSCOPE_API_KEY=sk-你的key
```
```yaml
# config.yaml（默认已是这样，通常无需改动）
answer:
  backend: api
  api_base: https://dashscope.aliyuncs.com/compatible-mode/v1
  api_key: ${DASHSCOPE_API_KEY}
  api_model: qwen-plus
  api_max_tokens: 8192
```

**切本地 Ollama：**

```bash
ollama pull qwen2.5:7b
ollama serve
```
```yaml
answer:
  backend: ollama
  ollama_model: qwen2.5:7b
  ollama_base: http://localhost:11434
```

**切完全离线**（抽取式，零依赖、零幻觉，代价是没有连贯成文）：

```yaml
answer:
  backend: template
```

切换后端请修改 `config.yaml` 并重启网页服务。

## 5. 常见运维动作

| 想做什么 | 怎么做 | 要重建索引吗 |
|---|---|---|
| 加一个术语/别名 | 编辑 `lexicon/concepts.yaml` | 要（元数据变了） |
| 加一位理论家 | 编辑 `lexicon/philosophers.yaml` | 要 |
| 换语料 | 替换 `data/` 语料并由离线维护流程重建索引 | 要 |
| 换嵌入模型 | 改 `embedding.model` | **必须全量重建** |
| 切生成后端 | 改 `answer.backend`（api / ollama / template） | 不要 |
| 换 API Key / 换服务商 | 改 `.env` 与 `answer.api_base` / `api_model` | 不要 |
| 调返回条数 | 改 `retrieval.final_top_k` | 不要 |
| 开/关问题闸门 | 改 `gate.enabled` | 不要 |
| 调闸门松紧 | 改 `gate.min_chars` / `gate.strict` | 不要 |
| 调语义相关性兜底 | 改 `gate.relevance` / `gate.relevance_threshold`（0.48 按 bge-base 标定） | 不要 |
| 开/关重排 | 改 `retrieval.rerank`（默认已开启，模型在 `models/bge-reranker-v2-m3`） | 不要 |
| 调重排延迟 | 改 `retrieval.rerank_top_k`（默认 12，须 > `final_top_k`）与 `retrieval.rerank_max_chars`（默认 256，0 = 整块不截断）；调小更快 | 不要 |

## 6. 排障

**`索引不存在：.../store`**
部署目录需包含完整的 `store/`，并让 `config.yaml` 的 `doc.store_dir` 指向它。

**`answer.api_key 为空` 或 API 调用失败**
生成层默认走云端。依次检查：① 项目根目录 `.env` 是否存在且 `DASHSCOPE_API_KEY` 已填；
② `config.yaml` 的 `answer.api_key` 是否为 `${DASHSCOPE_API_KEY}`。
网页会直接显示接口返回的可读错误（密钥错误 / 模型未开通 / 额度不足等）。
想先离线跑通：把 `answer.backend` 改成 `template` 并重启服务。

**中文乱码**
网页与 API 均使用 UTF-8。若查看服务日志乱码，在 Windows 终端执行 `chcp 65001`。

**`OSError: Can't load tokenizer` 或模型找不到**
`embedding.model` 写的是相对路径 `models/bge-base-zh-v1.5`，它相对 `config.yaml` 所在目录解析。
确认该目录下存在 `config.json` / `model.safetensors` / `tokenizer.json`。

**回答质量突然下降**
按顺序查：① `store/manifest.json` 里的 `embedding_backend` 是否与 `config.yaml` 一致
（换模型忘重建索引是最常见的坑）；② 网页检索里有没有你要的术语；
③ 运行 `python -m pytest` 看检索基线是否退化。

**问「你好」这类问题直接被跳过**
正常。问题闸门会拦下寒暄、问系统自身、实时信息、无主题碎片追问，以及无锚点又与语料无关的
问题（语义相关性兜底），跳过检索直接给出提示。
如需临时关闭闸门，把 `gate.enabled` 改成 `false` 并重启服务。
闸门的 26 条正负用例由 `tests/test_gate.py` 守护，`python -m pytest tests/test_gate.py` 可单独核对。
换过嵌入模型后要重新标定 `gate.relevance_threshold`，或直接关掉 `gate.relevance`。

**改了词典（别名 / 守卫 / 概念）后为什么要重建索引**
注解（理论家 / 概念 / 坐标 / 章节级标签）在构建索引时写进 `chunks.jsonl`、检索文本与
`terms.json`，改词典不会自动重算。重建后 `store/manifest.json` 里的
`annotation_version` 应为 `2`；服务加载旧索引时会在 stderr 提示「缺少新版注解」。

**启动时提示「分块参数已变更 / 词典文件已变更」怎么办**
这是索引指纹校验（manifest 记录 `chunk_params` 与四份词典 yaml 的内容 hash）：
索引是在旧配置或旧词典下构建的，已与当前配置对不上。请由离线维护流程重建 `store/`。
只改回答后端 / API 配置不涉及索引，不会触发该提示。

**服务启动后第一个请求很慢**
正常。嵌入模型冷启动约 20 秒，之后常驻内存。

## 7. 目录与产物说明

| 路径 | 内容 | 能否删 |
|---|---|---|
| `.env` | 你的 API Key（已 gitignore） | 可，但删了要重新填 |
| `data/哲学大纲_规范化_全集.txt` | 清洗后的语料（离线维护产物） | 可，需离线重新生成 |
| `store/*` | 索引（离线维护产物） | 可，需离线重建 |
| `models/bge-base-zh-v1.5/` | 嵌入模型（768 维） | 可，但需重新下载 |
| `models/bge-reranker-v2-m3/` | 重排模型（`retrieval.rerank` 开启时用） | 可，但需重新下载 |
| `lexicon/*.yaml` | 人工维护的词典 | **不要删**，是精度来源 |
| `philo_rag/web/` | 前端静态文件（`css/` 五层 + `js/` 十五模块，无构建步骤） | 可改，改了刷新即生效 |
| `tests/` | pytest 回归用例（解析 / 路由 / 闸门 / 引用 / 问答链路 / 检索基线 / 服务接口） | 可改，是自动化验收口径 |
| `outputs/` | 既有导出产物（网页端导出由浏览器下载） | 可 |

`store/manifest.json` 记录了构建时的嵌入后端、维度、块数、注解版本（`annotation_version`）与时间。
**换模型或改词典后如果忘了重建索引，看这个文件就能发现。**
