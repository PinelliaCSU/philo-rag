# 使用说明（运维手册）

面向「拿到这个目录、想直接跑起来」的人。分三步：**装环境 → 建索引 → 用**。

---

## 0. 环境

| 项 | 要求 |
|---|---|
| Python | 3.10+（本项目在 3.13 上实测） |
| 内存 | 建索引时约 1.5 GB（6630 块 × 768 维 float32 ≈ 20 MB 向量，其余是模型与分词） |
| 磁盘 | 约 1 GB（本地 bge 模型 + 索引 20 MB + 语料 4 MB + 依赖） |
| GPU | 不需要。CPU 建索引约 3 分钟，查询毫秒级 |
| 网络 | 仅「生成」一步需要（默认接云端大模型）；检索 / 向量化 / 重排全程离线 |

```bash
cd philo-rag
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
```

配好生成层的密钥（检索本身不需要）：

```bash
cp .env.example .env
# 编辑 .env：DASHSCOPE_API_KEY=sk-你的key
# 启动服务后打开 /api/stats 看生成后端；连通性问题会直接显示在界面错误行里
```

国内网络下载 `sentence-transformers` 依赖较慢时，加清华源：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 1. 建索引（只需一次）

仓库里已带清洗后的语料、索引与星图布局，通常**不需要**这一步。改了语料 / 分块参数 / 词典 /
嵌入模型时才重建：

```powershell
python scripts/build_index.py --prepare   # 采集清洗 → data/哲学大纲_规范化_全集.txt，再建索引
python scripts/build_index.py             # 只从现有规范全集重建索引 → store/
python scripts/build_starmap.py           # 重新生成星图布局 → philo_rag/web/data/starmap.json
```

`scripts/` 下只有这两个维护脚本（内部调用 prepare / ingest / index 与 networkx 布局），
不是用户 CLI：问答、术语、引文都只在 Web 界面里发生。

改了分块参数或词典后，**加载索引时的 stderr 提示**会指出索引已与配置不一致，照提示重建即可；
想看具体差异，直接删除 `store/` 后重建，或对比 `store/manifest.json` 里的
`chunk_params` / `lexicon_hashes` 与当前配置。

**预期结果**（用于判断是否正常）：

```
chunk_count        6630
quote_count        1144
unit_count         327
embedding_backend  sentence_transformer
vector_dim         768
```

索引里同时记录 169 位理论家 / 183 个概念 / 338 个体系单元。
`eval` 的基线是 `Hit@1 = 96.43% / Hit@3 = 100% / MRR = 0.9821`。

**想先验证链路、不想等 3 分钟？**
把 `config.yaml` 的 `doc.source` 临时改成 `data/sample_哲学史纲要.txt`（1.3 万字演示语料，
39 块 / 15 引文块），`build` 几秒完成，三类检索都能通。验证完改回全集路径重建即可。

## 2. 用

### 界面（唯一入口）

```powershell
python -m philo_rag --port 8000
```

打开 http://127.0.0.1:8000 。界面叫「星图纸页」：暗色雾面、无导航、无输入框；
星图只由回答命中的概念点亮；答案收束为一张无边界纸页；引用藏在句末极淡圆点里；
收藏按需从底部升起。

**提问方式不设选择器**。提交后纸页顶部只给一行自然语言确认：

| 确认行 | 什么情况 |
|---|---|
| 按单点查询理解：解释这个概念。 | 「什么是 X」「X 是什么意思」这类定位式提问 |
| 按范围查询理解：梳理这条脉络。 | 「X 在体系中的位置」「谈谈 X」这类主题式提问 |

行尾有低对比文字链「改成范围查询 / 聚焦到一点」，需要改主意时点它。低置信度默认按点查询走；
后端判定为 clarify 时前端会**自动**用点查询重问一次，仍无答案才显示「展开为范围查询」，
不弹澄清卡、不列选项。

**键盘**

| 键 | 行为 |
|---|---|
| `Enter` | 提交（中文输入法组字时不提交） |
| `Shift+Enter` | 换行 |
| `Esc` | 优先关闭最上层浮层；无浮层时清空输入；输入已空时回到空白首屏并重置会话 |
| 直接键入 | 空闲时任意可打印字符进入输入线 |
| `/` | 输入线为空且无浮层时打开低语层 |
| `S` | 收藏当前聚焦对象（问题 / 回答 / 引用 / 概念） |
| `F` | 打开星匣 |
| `Tab` | 输入线 → 纸页 → 引用点 → 星图 → 星匣触发区 |

**低语层**：屏幕中央偏下一条极淡单行输入，下方最多 5 条结果，上下键选择、`Enter` 打开、
`Esc` 关闭。前缀切换模式：

| 前缀 | 模式 | 数据源 |
|---|---|---|
| 默认 | 点（概念/术语） | `/api/concepts` 本地过滤 → `/api/concept`；无精确命中时 `/api/term` 语义兜底 |
| `引 ` | 引文 | `/api/quote`（说话人 / 概念 / 单元 / 关键词） |
| `脉 ` | 主题/范围 | `/api/ask`（`strategy: "theme"`） |
| `读 ` | 单元 | `/api/units` 本地匹配 + `/api/unit` |
| `图 ` | 体系地图 | 4×4 字头 × 位面单元网格（单元浏览，与星图布局无关） |
| `对 ` | 对比 | `/api/compare`（`A ↔ B` / `A vs B` / 两个空格分隔的词） |

**追问**：提交时带上 `conversation_id`，纸页顶部用一行极淡的「承自：<上一问>」表示上下文，
不显示追问 chips。会话在服务端内存里，30 分钟无操作即过期（`conversation` 段可调）；
过期后再追问会提示「对话已过期，请把问题重新完整描述一次」。`Esc`（输入为空）回到空白首屏并重置会话。

**五种纸页**共用同一种排版与底膜，只换内容：回答 / 概念 / 体系地图 / 单元阅读 / 对比。
单元阅读保留字号快捷键 `Ctrl+=` / `Ctrl+-` / `Ctrl+0`，滚动位置记在本地，不显示字号按钮。

**引用层**：含引用的句子句末有 3–4px 圆点，多引用先聚合为一个点；悬停给出短来源，
点击在底部升起薄层（作者 / 著作 / 章节页码 / 原文片段 / `chunk_id` 与字符区间 / 可复制引用格式），
薄层可钉住，`Esc` 关闭。引用不会点亮星图。

> 前端源码在 `frontend/`（Svelte 5 + Vite），构建产物提交在 `philo_rag/web/dist`，
> 因此 `pip install` 后直接可跑；改前端后需要 `npm run build` 重新生成产物。

## 3. 导出

导出只有两个入口，都在星匣里（`F` 打开），底部两条极淡文字链：

| 入口 | 内容 |
|---|---|
| 导出 JSON（全部回答） | 全部 `answers` / `citations` / `litNodes`，不依赖收藏，适合备份 |
| 导出 Markdown（收藏） | 四类收藏（问题 / 回答 / 引用 / 概念）按类型分节，含旧批注 |

不再提供 md / jsonl / csv / txt 的批量渲染与 `--out` 落盘：交付形态只有 Web 服务。

## 4. 生成层：默认云端，可切本地 / 离线

生成层由 `answer.backend` 决定，三选一，**切换不需要重建索引**：

| 后端 | 说明 | 需要什么 |
|---|---|---|
| `api`（默认） | 任意 OpenAI 兼容 `/chat/completions`，默认接阿里云百炼 | 一把 API Key |
| `ollama` | 本地模型，数据不出本机 | 常驻 Ollama 服务 |
| `template` | 离线抽取式：从检索结果挑出相关句子并分组，不做生成 | 无 |

**默认（云端）**——密钥只放 `.env`，`config.yaml` 用 `${VAR}` 引用，可安全提交：

```bash
cp .env.example .env      # 编辑：DASHSCOPE_API_KEY=sk-你的key
```
```yaml
# config.yaml（默认已是这样，通常无需改动）
answer:
  backend: api
  api_base: https://dashscope.aliyuncs.com/compatible-mode/v1
  api_key: ${DASHSCOPE_API_KEY}
  api_model: qwen-plus
  api_max_tokens: 8192
```

**切本地 Ollama：**

```bash
ollama pull qwen2.5:7b
ollama serve
```
```yaml
answer:
  backend: ollama
  ollama_model: qwen2.5:7b
  ollama_base: http://localhost:11434
```

**切完全离线**（抽取式，零依赖、零幻觉，代价是没有连贯成文）：

```yaml
answer:
  backend: template
```

命令行也可临时覆盖，便于对比：`ask "问题" --backend template|ollama|api`。

## 5. 常见运维动作

| 想做什么 | 怎么做 | 要重建索引吗 |
|---|---|---|
| 加一个术语/别名 | 编辑 `lexicon/concepts.yaml` | 要（元数据变了） |
| 加一位理论家 | 编辑 `lexicon/philosophers.yaml` | 要 |
| 换语料 | 改 `doc.raw` → `prepare` | 要 |
| 换嵌入模型 | 改 `embedding.model` | **必须全量重建** |
| 切生成后端 | 改 `answer.backend`（api / ollama / template） | 不要 |
| 换 API Key / 换服务商 | 改 `.env` 与 `answer.api_base` / `api_model` | 不要 |
| 调返回条数 | 改 `retrieval.final_top_k` | 不要 |
| 开/关问题闸门 | 改 `gate.enabled`（或 `ask --no-gate`） | 不要 |
| 调闸门松紧 | 改 `gate.min_chars` / `gate.strict` | 不要 |
| 调语义相关性兜底 | 改 `gate.relevance` / `gate.relevance_threshold`（0.48 按 bge-base 标定） | 不要 |
| 开/关重排 | 改 `retrieval.rerank`（默认已开启，模型在 `models/bge-reranker-v2-m3`） | 不要 |
| 调重排延迟 | 改 `retrieval.rerank_top_k`（默认 12，须 > `final_top_k`）与 `retrieval.rerank_max_chars`（默认 256，0 = 整块不截断）；调小更快 | 不要 |
| 换星图布局 | ~BT~python scripts/build_starmap.py~BT~ | 不要（星图是独立 JSON） |

## 6. 排障

**`索引不存在：.../store`**
先跑 `python scripts/build_index.py`。

**`answer.api_key 为空` 或 API 调用失败**
生成层默认走云端。依次检查：① 项目根目录 `.env` 是否存在且 `DASHSCOPE_API_KEY` 已填；
② `config.yaml` 的 `answer.api_key` 是否为 ${DASHSCOPE_API_KEY}`；
③ 直接看界面上的错误行——服务端把 HTTP 错误体转成可读文案，会写明
「密钥错误 / 模型未开通 / 额度不足」。
想先离线跑通：把 `answer.backend` 改成 `template`（不需要联网，也不需要 Key）。

**界面一片空白 / 报「前端产物缺失」**
`philo_rag/web/dist` 没构建出来。在 `frontend/` 里跑 `npm install && npm run build`；
受限环境用 `npm run build:restricted`。

**`OSError: Can't load tokenizer` 或模型找不到**
`embedding.model` 写的是相对路径 `models/bge-base-zh-v1.5`，它相对 `config.yaml` 所在目录解析。
确认该目录下存在 `config.json` / `model.safetensors` / `tokenizer.json`。

**想彻底离线/零依赖验证链路**
```yaml
embedding:
  backend: hashing
  dim: 512
retrieval:
  dense_weight: 0.3      # hashing 只是词法近似，降低它的权重
```
然后 `python scripts/build_index.py`。效果会明显变差，但能在没有 numpy 之外任何依赖的
环境里验证链路是否通。

**回答质量突然下降**
按顺序查：① `GET /api/stats` 里 `embedding_backend` 是否与配置一致（换模型忘重建索引是最常见的坑）
② `GET /api/facets` 里有没有你要的术语 ③ 跑 `python -m pytest` 看检索基线是否退化。

**问「你好」这类问题直接被跳过**
正常。问题闸门会拦下寒暄、问系统自身、实时信息、无主题碎片追问，以及无锚点又与语料无关的
问题（语义相关性兜底），跳过检索直接给出提示。
想强制送进检索：把 `gate.enabled` 改成 `false`。
想核对闸门有没有误伤哲学提问：跑 `python -m pytest tests/test_gate.py`——用例表在
`tests/gate_cases.py`（26 条正负用例 + 语义相关性兜底用例），见 docs/架构设计.md §13.1。
换过嵌入模型后要重新标定 `gate.relevance_threshold`，或直接关掉 `gate.relevance`。

**为什么问答不能按单元 / 理论家筛选**
溯源问答固定全文检索。筛选会先缩小候选池，把承载「概念定义」的段落（常在前言、总纲或
别的单元）排除在外，导致回答内容被截断。需要按维度浏览请用概念纸页、体系地图与低语层 `引`。

**改了词典（别名 / 守卫 / 概念）后为什么要重建索引**
注解（理论家 / 概念 / 坐标 / 章节级标签）在建索引时写进 `chunks.jsonl`、检索文本与
`terms.json`，改词典不会自动重算。重建后 `store/manifest.json` 里的
`annotation_version` 应为 `2`；加载旧索引时会在 stderr 提示「缺少新版注解」。
守卫规则变化会影响注解数量（见 docs/架构设计.md §六），重建后请顺手跑一次 pytest 的检索基线。
星图的 `lexicon_hashes` 与 manifest 不一致时界面不报错，只在控制台警告——记得重跑
`python scripts/build_starmap.py`。

**启动时提示「分块参数已变更 / 词典文件已变更」怎么办**
这是索引指纹校验（manifest 记录 `chunk_params` 与四份词典 yaml 的内容 hash）：
你在建索引之后改过分块参数或词典，索引已经与配置对不上。按提示重建即可：
`python scripts/build_index.py`。差异清单由 `Store.check_consistency` 计算，
在加载索引时打印到 stderr。只改回答后端 / API 配置不涉及索引，不会触发该提示。

**服务启动后第一个请求很慢**
正常。嵌入模型冷启动约 20 秒，之后常驻内存。

## 7. 目录与产物说明

| 路径 | 内容 | 能否删 |
|---|---|---|
| `.env` | 你的 API Key（已 gitignore） | 可，但删了要重新填 |
| `data/哲学大纲_规范化_全集.txt` | 清洗后的语料（`prepare` 产物） | 可，`prepare` 能重建 |
| `store/*` | 索引（`build` 产物） | 可，`build` 能重建 |
| `models/bge-base-zh-v1.5/` | 嵌入模型（768 维） | 可，但需重新下载 |
| `models/bge-reranker-v2-m3/` | 重排模型（`retrieval.rerank` 开启时用） | 可，但需重新下载 |
| `lexicon/*.yaml` | 人工维护的词典 | **不要删**，是精度来源 |
| `philo_rag/web/dist/` | Vite 构建产物（提交进仓库，pip 装完即可运行） | 可，`npm run build` 能重建 |
| `philo_rag/web/data/starmap.json` | 星图布局（节点 / 边 / 坐标 / 词典指纹） | 可，`scripts/build_starmap.py` 能重建 |
| `frontend/` | Svelte 5 + Vite 源码、Vitest 与 Playwright 用例 | **不要删**，是前端唯一源码 |
| `tests/` | pytest 回归用例（解析 / 路由 / 闸门 / 引用 / 问答链路 / 检索基线 / 服务接口 / 星图） | 可改，是自动化验收口径 |
| `scripts/build_index.py` | 重建索引（维护脚本） | 可 |
| `scripts/build_starmap.py` | 重建星图布局（维护脚本） | 可 |

`store/manifest.json` 记录了构建时的嵌入后端、维度、块数、注解版本（`annotation_version`）与时间。
**换模型或改词典后如果忘了重建索引，看这个文件就能发现。**
