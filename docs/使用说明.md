# 使用说明（运维手册）

面向「拿到这个目录、想直接跑起来」的人。分三步：**装环境 → 建索引 → 用**。

---

## 0. 环境

| 项 | 要求 |
|---|---|
| Python | 3.10+（本项目在 3.13 上实测） |
| 内存 | 建索引时约 1.5 GB（6630 块 × 768 维 float32 ≈ 20 MB 向量，其余是模型与分词） |
| 磁盘 | 约 1 GB（本地 bge 模型 + 索引 20 MB + 语料 4 MB + 依赖） |
| GPU | 不需要。CPU 建索引约 3 分钟，查询毫秒级 |
| 网络 | 仅「生成」一步需要（默认接云端大模型）；检索 / 向量化 / 重排全程离线 |

```bash
cd philo-rag
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
```

配好生成层的密钥（检索本身不需要）：

```bash
cp .env.example .env
# 编辑 .env：DASHSCOPE_API_KEY=sk-你的key
python scripts/check_api.py       # 校验 key 与端点是否连通
```

国内网络下载 `sentence-transformers` 依赖较慢时，加清华源：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 1. 建索引（只需一次）

```bash
python -m philo_rag.cli demo
```

`demo` 会依次：采集清洗 PDF → 构建索引 → 跑通三类检索自检。全程约 5 分钟。
看到 `==== 自检通过 ====` 就说明一切正常。

> 自检的问答环节**固定用离线 `template` 后端**，因此没配 API Key 也能跑通整条检索链路；
> 若 `config.yaml` 配了 `api` / `ollama`，`demo` 末尾会额外做一次真实生成调用探测。

也可以分步做：

```bash
python -m philo_rag.cli prepare   # 采集清洗 → data/哲学大纲_规范化_全集.txt
python -m philo_rag.cli build     # 建索引   → store/
python -m philo_rag.cli stats     # 看一眼概览
```

**预期结果**（用于判断是否正常）：

```
chunk_count        6630
quote_count        1144
unit_count         327
embedding_backend  sentence_transformer
vector_dim         768
```

索引里同时记录 154 位理论家 / 105 个概念 / 338 个体系单元。
`eval` 的基线是 `Hit@1 = 96.43% / Hit@3 = 100% / MRR = 0.9821`。

**想先验证链路、不想等 3 分钟？**
把 `config.yaml` 的 `doc.source` 临时改成 `data/sample_哲学史纲要.txt`（1.3 万字演示语料，
39 块 / 15 引文块），`build` 几秒完成，三类检索都能通。验证完改回全集路径重建即可。

## 2. 用

### 命令行

```bash
# 溯源回答：默认自动判定（定义式提问 → 点查询；主题式提问 → 范围查询）
python -m philo_rag.cli ask "什么是字头？"          # → 点查询，数百字
python -m philo_rag.cli ask "马克思在体系中的位置"   # → 范围查询，按单元分节成文
python -m philo_rag.cli ask "谈谈精神分析"          # → 范围查询；词典未收录 → 种子模式自动锚定

# 强制指定策略（用于对比两条召回链路）
python -m philo_rag.cli ask --strategy point "精神分析"
python -m philo_rag.cli ask --strategy theme "精神分析"

# 临时切换生成后端（对比同一问题的离线抽取式 vs 云端生成）
python -m philo_rag.cli ask --backend template "什么是字头？"
python -m philo_rag.cli ask --backend api      "什么是字头？"

# 关闭问题闸门，强制把问题送进检索（调试用）
python -m philo_rag.cli ask "随便问问" --no-gate

# 术语
python -m philo_rag.cli term "大他者"
python -m philo_rag.cli term "客体小a" --format json

# 引文检索：说话人（精确归因）/ 相关理论家（含语境）/ 单元 + 概念交叉过滤
python -m philo_rag.cli quote --speaker 拉康 --limit 10
python -m philo_rag.cli quote --philosopher 黑格尔 --concept 辩证法
python -m philo_rag.cli quote --unit 4 --format csv --out outputs/字头4引文.csv

# 体系浏览
python -m philo_rag.cli facets
```

> **要不要手动指定 `--strategy`？**
> 一般不需要——`ask` 会按提问自动判定：
> 定义式提问（「什么是 X」「X 是什么意思」）走**点查询**，top-8、数百字；
> 主题式提问（「X 在体系中的位置」「谈谈 X」「X 的思想脉络」）或直接输入一个主题词，
> 走**范围查询**，召回数百块并按单元聚合，输出 4000 字以上的结构化回答。
> 判定只做粗筛，拿不准时用 `--strategy point|theme` 显式指定即可。
> 差距的实测数据见 [`检索问答与专题提炼的差距诊断.md`](检索问答与专题提炼的差距诊断.md)。

### Web 界面

```bash
python -m philo_rag.cli serve --port 8000
```

打开 http://127.0.0.1:8000 ，四个页签：溯源回答 / 术语检索 / 引文检索 / 分面·体系。

- **溯源回答**：输入框同时接受「问题」和「主题词」。定义式提问得到少而准的答案；
  主题式提问得到按数值单元分节的深度回答，并在上方多一张**聚合概览**卡片
  （命中块数、覆盖单元、共现理论家），便于核对主题集中度。卡片上会标注本次走的是
  「点查询」还是「范围查询」。
- **引文检索**：四个下拉（单元 / 理论家 / 说话人 / 概念）+ 关键词。注意「理论家」是
  **相关理论家**（引文所在段落谈到他即命中，召回高）；「说话人」只认有引述标记的精确归因
  （覆盖低但不会张冠李戴）——要「某人的原话」请用说话人。
- **分面·体系**：卷级统计、概念与理论家分布、数值单元卡片；点击任一卡片会把它转成一个
  自然语言问题并直接提问（如点「大他者」→ 问「什么是大他者？」；点某理论家 → 问「X 的核心思想是什么？」，
  自动走范围查询）。
- 问答页没有筛选下拉——溯源回答固定对整篇语料做全文检索，避免筛选截断概念内容。

> 首次提问会有几秒延迟（加载嵌入模型），之后每次查询都在 1 秒内。
> 范围查询的聚合是纯元数据 + 词法操作，不额外过嵌入模型。

## 3. 导出结果

所有命令都支持 `--format` 与 `--out`：

```bash
python -m philo_rag.cli ask   "什么是四话语？"      --format md   --out outputs/四话语.md
python -m philo_rag.cli ask   "马克思在体系中的位置" --format md   --out outputs/马克思专题.md
python -m philo_rag.cli ask   "精神分析"            --format json --out outputs/精神分析.json
python -m philo_rag.cli term  "辩证法"              --format json --out outputs/辩证法.json
python -m philo_rag.cli quote --speaker 拉康        --format csv  --out outputs/拉康引文.csv
python -m philo_rag.cli eval                        --format json --out outputs/评测.json
```

格式：`md`（默认）/ `json` / `jsonl` / `csv` / `txt`。
不指定 `--out` 时打印到终端。默认输出目录由 `config.yaml` 的 `output.dir` 决定。

## 4. 生成层：默认云端，可切本地 / 离线

生成层由 `answer.backend` 决定，三选一，**切换不需要重建索引**：

| 后端 | 说明 | 需要什么 |
|---|---|---|
| `api`（默认） | 任意 OpenAI 兼容 `/chat/completions`，默认接阿里云百炼 | 一把 API Key |
| `ollama` | 本地模型，数据不出本机 | 常驻 Ollama 服务 |
| `template` | 离线抽取式：从检索结果挑出相关句子并分组，不做生成 | 无 |

**默认（云端）**——密钥只放 `.env`，`config.yaml` 用 `${VAR}` 引用，可安全提交：

```bash
cp .env.example .env      # 编辑：DASHSCOPE_API_KEY=sk-你的key
python scripts/check_api.py
```
```yaml
# config.yaml（默认已是这样，通常无需改动）
answer:
  backend: api
  api_base: https://dashscope.aliyuncs.com/compatible-mode/v1
  api_key: ${DASHSCOPE_API_KEY}
  api_model: qwen-plus
  api_max_tokens: 8192
```

**切本地 Ollama：**

```bash
ollama pull qwen2.5:7b
ollama serve
```
```yaml
answer:
  backend: ollama
  ollama_model: qwen2.5:7b
  ollama_base: http://localhost:11434
```

**切完全离线**（抽取式，零依赖、零幻觉，代价是没有连贯成文）：

```yaml
answer:
  backend: template
```

命令行也可临时覆盖，便于对比：`ask "问题" --backend template|ollama|api`。

## 5. 常见运维动作

| 想做什么 | 怎么做 | 要重建索引吗 |
|---|---|---|
| 加一个术语/别名 | 编辑 `lexicon/concepts.yaml` | 要（元数据变了） |
| 加一位理论家 | 编辑 `lexicon/philosophers.yaml` | 要 |
| 换语料 | 改 `doc.raw` → `prepare` | 要 |
| 换嵌入模型 | 改 `embedding.model` | **必须全量重建** |
| 切生成后端 | 改 `answer.backend`（api / ollama / template） | 不要 |
| 换 API Key / 换服务商 | 改 `.env` 与 `answer.api_base` / `api_model` | 不要 |
| 调返回条数 | 改 `retrieval.final_top_k` | 不要 |
| 开/关问题闸门 | 改 `gate.enabled`（或 `ask --no-gate`） | 不要 |
| 调闸门松紧 | 改 `gate.min_chars` / `gate.strict` | 不要 |
| 调语义相关性兜底 | 改 `gate.relevance` / `gate.relevance_threshold`（0.48 按 bge-base 标定） | 不要 |
| 开/关重排 | 改 `retrieval.rerank`（默认已开启，模型在 `models/bge-reranker-v2-m3`） | 不要 |
| 调重排延迟 | 改 `retrieval.rerank_top_k`（默认 12，须 > `final_top_k`）与 `retrieval.rerank_max_chars`（默认 256，0 = 整块不截断）；调小更快 | 不要 |
| 换输出格式 | `output.format` 或 `--format` | 不要 |

## 6. 排障

**`索引不存在：.../store`**
先跑 `python -m philo_rag.cli build`。

**`answer.api_key 为空` 或 API 调用失败**
生成层默认走云端。依次检查：① 项目根目录 `.env` 是否存在且 `DASHSCOPE_API_KEY` 已填；
② `config.yaml` 的 `answer.api_key` 是否为 `${DASHSCOPE_API_KEY}`；
③ 跑 `python scripts/check_api.py`——它会把 HTTP 错误体带出来，可直接看到
「密钥错误 / 模型未开通 / 额度不足」等具体原因。
想先离线跑通：`ask "问题" --backend template`，或把 `answer.backend` 改成 `template`。

**中文乱码**
CLI 已强制 UTF-8 输出。若仍乱码，在 Windows 上执行 `chcp 65001`。

**`OSError: Can't load tokenizer` 或模型找不到**
`embedding.model` 写的是相对路径 `models/bge-base-zh-v1.5`，它相对 `config.yaml` 所在目录解析。
确认该目录下存在 `config.json` / `model.safetensors` / `tokenizer.json`。

**想彻底离线/零依赖验证链路**
```yaml
embedding:
  backend: hashing
  dim: 512
retrieval:
  dense_weight: 0.3      # hashing 只是词法近似，降低它的权重
```
然后 `build`。效果会明显变差，但能在没有 numpy 之外任何依赖的环境里验证链路是否通。

**回答质量突然下降**
按顺序查：① `stats` 里 `embedding_backend` 是否与配置一致（换模型忘重建索引是最常见的坑）
② `facets` 里有没有你要的术语 ③ 跑 `eval` 看基线是否退化。

**问「你好」这类问题直接被跳过**
正常。问题闸门会拦下寒暄、问系统自身、实时信息、无主题碎片追问，以及无锚点又与语料无关的
问题（语义相关性兜底），跳过检索直接给出提示。
想强制送进检索：`ask "…" --no-gate`，或把 `gate.enabled` 改成 `false`。
想核对闸门有没有误伤哲学提问：`python scripts/check_gate.py`（26 条正负用例）；
要连语义相关性兜底一起核对：`python scripts/check_gate.py --relevance`（40 条，需已建索引）。
换过嵌入模型后要重新标定 `gate.relevance_threshold`，或直接关掉 `gate.relevance`。

**`ask --unit` / `--concept` 这些筛选参数怎么没了**
自 v1.1 起溯源问答固定全文检索，筛选参数已移除。原因是筛选会先缩小候选池，
把承载「概念定义」的段落（常在前言、总纲或别的单元）排除在外，导致回答内容被截断。
需要按维度浏览请改用 `term`（术语）、`facets`（分面）与引文检索。

**服务启动后第一个请求很慢**
正常。嵌入模型冷启动约 20 秒，之后常驻内存。

## 7. 目录与产物说明

| 路径 | 内容 | 能否删 |
|---|---|---|
| `.env` | 你的 API Key（已 gitignore） | 可，但删了要重新填 |
| `data/哲学大纲_规范化_全集.txt` | 清洗后的语料（`prepare` 产物） | 可，`prepare` 能重建 |
| `store/*` | 索引（`build` 产物） | 可，`build` 能重建 |
| `models/bge-base-zh-v1.5/` | 嵌入模型（768 维） | 可，但需重新下载 |
| `models/bge-reranker-v2-m3/` | 重排模型（`retrieval.rerank` 开启时用） | 可，但需重新下载 |
| `lexicon/*.yaml` | 人工维护的词典 | **不要删**，是精度来源 |
| `scripts/gen_taxonomy.py` | 从语料重建体系目录（改语料后重跑） | 可 |
| `scripts/check_speaker.py` | 引文说话人归因巡检 | 可 |
| `scripts/check_gate.py` | 问题闸门巡检（放行 / 拦截用例） | 可 |
| `scripts/check_api.py` | 生成层 API 连通性自检 | 可 |
| `outputs/` | 导出的结果 | 可 |

`store/manifest.json` 记录了构建时的嵌入后端、维度、块数、时间。
**换模型或改词典后如果忘了重建索引，看这个文件就能发现。**
