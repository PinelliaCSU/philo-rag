## 二 诊断：三个病灶

### 病灶 A｜「拼接」发生在 LLM 之前

- 证据 1：`outputs/溯源回答_精神分析.md:34` 正文首句为
  `精神分析应当是一项清醒的活动，不是炼丹修仙。】`
  ——句首是**半个 `【释：…】` 标注**，句子被从原文中间切断。
- 证据 2：`outputs/溯源回答_马克思.md:22` 出现 `Hegelia n`（PDF 清洗残留），
  同样是原文碎片被原样拼上。
- 机制：`philo_rag/answer.py:193 _topic_evidence` 对每个命中块只挑 **1 句**，8 块拼 8 句；
  `docs/检索问答与专题提炼的差距诊断.md:107` 实测信息利用率 **29%**（证据句均 104 字 vs 块均 319 字）。
- 判断：**送给模型的证据本身就是断链的**。模型被迫「补全」，这就是幻觉的入口，
  也是「拼接嫌疑」的真正来源。它在 `template` 后端就已经发生，与模型无关。

### 病灶 B｜「AI 味」是提示词里写死的

证据（`philo_rag/answer.py`）：

| 行 | 现有要求 | 为什么它是问题 |
|---|---|---|
| `:62` | 「第一段第一句用一句日常语言给出结论，这一句里不出现本书特有的术语」 | 「先说人话」是科普博主腔的第一特征 |
| `:63` | 「每个术语**第一次**出现时紧跟「（即……）」补一句不超过 25 字的白话解释」 | 高密度内联解释会把哲学文本切成「术语+白话」的碎节奏 |
| `:66` | 「分成 3—5 个自然段，依次说明：核心定义、形成机制或论证路径、不同理论位置的张力，最后给出一句总结」 | 这是通用的 LLM 文章骨架，不是原书的文体 |

三条合起来就是「科普博主腔」的配方。为「晦涩」打的补丁（`:63` 的内联解释）
恰好成了 AI 味的来源；`config.yaml:104-106` 记录了 700→850 字的反复放宽，
说明这个补丁一直在与模型超限对抗。

- 判断：**AI 味不是模型的锅，是提示词的任务定义错了**——
  它要模型当「讲解员」，而这本书需要的是「编者」。

### 病灶 C｜语料是坐标系，系统只当普通文本用

- 事实：语料每个单元带 **4 位坐标**（场域论 / 本体论 / 认识论 / 目的论，各取 1–4）。
  语料前言【释：】明言：「本体系以四位数字编号……首位数字即所谓『字头』」；
  体系表见 `config.yaml:23`（338 单元）。
- 现状：这套坐标只被用于元数据标签与 facets 计数，
  **没有进入任何检索或生成逻辑**——不能问「1-2-3-4 讲什么」，不能做单元对照，无谱系方向性。
- 判断：这是「把一本书挖到极致」唯一有护城河的方向。
  通用 RAG **没有坐标系**，所以这个能力别人抄不走，只能靠语料本身。

### 三处附带待修事实

1. 词典无主题层：`差距诊断.md:145-151` 实测「精神分析」这类流派级词元数据命中 **0 块**；
   `lexicon/concepts.yaml` 只覆盖「概念」与「理论家」两层。
2. 引用不可回跳：`outputs/溯源回答_马克思.md:63` 显示字符区间 `1567007-1578544` **只作为文本**
   嵌在 citation 字符串里；`philo_rag/web/app.js:251` 仅渲染该字符串为文本。
   即 README 宣称的「答案可点击跳转原文」目前**不成立**。
3. 检索基线文档不一致（见第一节）。

## 三 三阶段路线图

```
阶段一【可信】  LLM 从「作者」降级为「胶水」：幻觉与 AI 味按量级压掉，可信度变成可测数字
阶段二【收敛】  入口生态从「三个孤立检索页」收敛为「一个问答 + 可召唤的概念卡」

```

**总口径：检索基线冻结**——`eval` 的 Hit@1 / Hit@3 / MRR 不得下降；
所有生成层改动必须用新增的 grounded 指标 + 盲评衡量，不接受「凭手感说变好了」。

## 四 阶段一任务书【可信】

> 设计原则一句话：**LLM 只做胶水，不做正文。**
>
> ```
> 检索 → 证据整备（确定性） → 结构规划（确定性） → 衔接语生成（LLM，极小剂量）
>      → 引用核对（确定性） → 渲染（确定性）
> ```

### T1-A｜引用核对层 + 可信度度量 ★最先做

- **目标**：新增 `philo_rag/verify.py` 与 `scripts/check_grounded.py`。
  对任意回答逐句判定三档：
  `grounded`（可定位到某证据的连续片段）/ `paraphrase`（高重叠但非连续）/ `ungrounded`（无支撑），
  输出比率与未支撑句子清单。
- **边界**：只新增上述两个文件；对 `answer.py` 仅只读导入，**不得修改**。
- **约束**：
  - 必须能对**已有的 `outputs/*.md` 样本离线跑**（不重跑生成、不产生 API 费用）；
  - 中文按 4-gram 起步，阈值参数化；
  - 判定逻辑与模型无关（换模型后仍然可用）。
- **验收标准**：
  - `template` 后端的 grounded 率 ≥ 95%（它是零幻觉形态，用作校准点）；
  - 能逐条列出 `ungrounded` 句子的原文；
  - 产出 6 条抽样题的 grounded 率基线表。
- **必须回报的证据**：脚本路径、基线数字表、`ungrounded` 句样例、`eval` 实跑三指标。

**为什么先做**：原文说的是「存在拼接与幻觉的**嫌疑**」——嫌疑之所以是嫌疑，是因为不可测。
没有这个数字，阶段一改完无法判断变好还是变坏，也无法决定将来是否需要换模型。

### T1-B｜生成层重构（本阶段最大一块，独占 `answer.py` / `output.py`）

- **目标**：把「LLM 写正文」改为「**代码排版 + LLM 只写衔接语**」。四件事一起做：
  1. **证据整备**：point 路径不再「每块取 1 句」，改为取「含命中句的完整段 + 相邻块合并」。
     **复用** `philo_rag/theme.py:207 _aggregate_by_unit(store, lex, blocks, group_gap)`——
     签名已核实可直接调用，**不要重写**。
  2. **template 后端升级为「可信基线编辑稿」**：每节 = 原文完整段（逐字不改）+ 坐标出处；
     节标题、排序、分节全部由**代码**按单元坐标与密度决定，不依赖模型。
  3. **新提示词**：删掉 `answer.py:62/63/66` 三条 AI 腔配方；改为
     「原文即正文，你只负责节标题与单元串接语，每节衔接语 ≤ `bridge_max_chars`」；
     **旧提示词保留为 `legacy` 档**，用于 A/B 对照。
  4. **受限输出 + 术语外置**：模型输出结构化分节（JSON / 标记），由 `output.py` 确定性渲染，
     消灭排版漂移；术语解释移出正文，作为注解数组随 payload 传给前端侧栏。
- **边界**：
  - `philo_rag/answer.py`、`philo_rag/output.py`、`config.yaml`
    （新增 `answer.bridge_max_chars`、`answer.quote_first`、`answer.prompt_style: quote_first|legacy`）；
  - 顺带把已 1220 行的 `answer.py` 拆出 `answer_evidence.py` / `answer_prompt.py`（属重构，非新增功能）；
  - 同步修订 `docs/架构设计.md:611` 的过期基线。
- **约束**：**不得改** `retrieve.py` / `theme.py` 的召回与排序逻辑；旧模式必须仍可切换。
- **验收标准**：
  - 6 条抽样题（字头 / 存在者整体 / 大他者 / 马克思 / 精神分析 / 辩证法）新旧对比：
    grounded 率上升、**原文占比 ≥ 80%**；
  - `eval` 三指标不退化（96.43% / 100% / 0.9821）；
  - 交付新旧对照表 + 一份新格式完整样本供盲评。
- **必须回报的证据**：改动 diff 摘要、新旧 grounded 率与原文占比、`eval` 三指标、新格式样本。

### T1-C｜引用可回跳

- **目标**：前端点 `[1]` 能展开该段原文并高亮命中区间。
- **边界**：先核实 citations payload 是否已带可用的 `char_start` / `char_end` 字段——
  **已带则只动 `web/app.js`**；未带才允许动 `output.py`（与 T1-B 串行）。
- **验收标准**：点击引用 → 展开原文 → 高亮区间与引用一致。

## 八 风险与取舍

| 风险 | 应对 |
|---|---|
| 原文优先会让回答更长、更晦涩 | 用**结构**降门槛而非用白话降门槛：节标题由代码按坐标生成，术语走侧栏注解 |
| grounded 匹配天生惩罚改写 | 阈值参数化 + 独立 `paraphrase` 档，避免把正常衔接误判成幻觉 |
| 大段原文引用（观感 / 版权） | 默认折叠、可展开 |
| `answer.py` 已 1220 行，继续加会失控 | T1-B 内顺手拆出 `answer_evidence.py` / `answer_prompt.py` |
| 生成层改动无回归保护 | 先补 T1-A 的 grounded 基线，再动生成层 |

## 九 明确不做（YAGNI）

- **不上 Qdrant / ES / Postgres**：6630 块、20 MB 向量，numpy 点积是毫秒级；
  D5 已定单书，`docs/架构设计.md:643` 列的 P4 规模化在此决策下无收益。
- **不引入 LangChain / LlamaIndex**：现有链路只有 6 个环节，编排框架只增加黑箱。
- **不做模型微调**、**不做多文档 / 多用户 / 权限**。
- **不新增第二个问答入口**：`差距诊断.md:9-16` 已否决过一版「并列新增 theme 入口」，
  同样的错误不再犯。

## 十 派发与验收纪律

本会话无子代理模型选择能力（无 `list_subagent_models`），按默认继承派发，不写 route 行。

每个任务的验收标准都落到**可复跑的证据**上：`eval` 实跑数字、`check_grounded` 输出、
新格式样本、diff 阅读。不接受「我觉得好多了」。

子代理必须先自检再回报；规划者复审后才算完成。**验收不通过就带证据重新派发，
规划者不接手改它的代码**（同一任务书最多重派两次）。

### 待用户确认的两个决策点（不阻塞开工）

1. P-a 的衔接语剂量默认 60 字是否合适；
2. 原文优先后回答会变长，是否接受「默认折叠长引文」的呈现方式。
