# 检索问答与专题提炼的差距诊断与优化方案

> 诊断对象：`philo-rag` 知识库（语料 6630 块 / 327 单元 / 768 维）
> 对照对象：本目录下既有的专题提炼稿（`马克思思想_主题提炼`、`黑格尔思想_主题提炼` 等）
> 结论先行：**这不是「检索不准」，而是「链路的任务类型不匹配」——用点查询做了范围查询。**

---

## 〇、方案修正（v1.3）

本文初稿给出的方案是「**并列新增一条 `theme` 链路**」。这是**对问题的误判**——
用户要的不是多一个专题提炼版块，而是**让「溯源回答」这个版块本身**在主题式提问上
达到既有专题提炼稿的质量与主题集中度。初稿把「手段」（范围查询）当成了「目的」（多一个入口），
结果是同一个知识库出现两个问答入口：用户要先判断自己的问题属于哪一类，两处的引用格式、
导出格式、界面交互还要各维护一套。

**修正后的方案：类型判定进链路内部，只保留一个入口。**

```
                    ┌─ 点查询 point ─▶ hybrid_search（top-8，少而准）
提问 ─▶ 闸门 ─▶ 类型判定 ┤
                    └─ 范围查询 theme ─▶ theme_search（数百块 + 单元聚合 + 段落群）
                                              │
                        两条策略共用同一返回结构（answer + citations）
```

具体落地：

| 项 | 初稿（已废弃） | 修正后（当前实现） |
|---|---|---|
| 入口 | `ask` + `theme` 两个命令 / 两个页签 | **只有 `ask` 一个入口**；`--strategy point\|theme` 可强制 |
| 判定 | 由用户自己选命令 | `classify_question()` 在链路内部自动判定 |
| 输出层 | 新增 `theme` 渲染器 | 复用 `render_answer`，范围查询结果多渲染一段「聚合概览」 |
| Web | 新增「专题提炼」页签 | 溯源回答页一个输入框，结果卡片上标注本次策略 |
| `theme.py` | 与 `retrieve.py` 并列的独立链路 | `answer()` 内部的一个分支策略 |

**本文以下各节保留初稿的诊断内容（环节定位、实测数据仍然有效），但第五、六节的
「落地方案」已按上表修正。** 实测结论不变：同一个入口在主题式提问上，
召回从 8 块提升到 263 块、覆盖单元从 13 个提升到 77 个、输出从 895 字提升到 4000 字以上。

## 一、结论速览

当前 `ask` 链路是一条**引用溯源问答**（citation-grounded QA）流水线：它被设计来回答
「这句话出自哪里」「X 是什么意思」，追求的是**少而准**（final_top_k = 8，Hit@1 = 96.4%）。

而「专题提炼」是**主题综合**（thematic synthesis）：它要回答「全书如何论述 X」，
需要的是**多而全 + 结构化组织**。

用户把后者的问题交给前者，得到的必然是「8 条互不相干的摘录」。差距不在某一处参数，
而在整条链路的**召回量、组织维度、上下文预算、提示词长度约束**四个环节上系统性错配。

## 二、两条链路的实测对照

对同一批主题，用溯源回答的两条策略（`--strategy point` 与 `--strategy theme`）分别实测如下
（`point` 即初稿所说的 `ask` 点查询，`theme` 即初稿所说的专题综合；下同）：

| 主题 | point 召回 | point 覆盖单元 | point 覆盖卷 | point 相邻块 | theme 召回 | theme 覆盖单元 | theme 覆盖卷 |
|---|---|---|---|---|---|---|---|
| 马克思 | 20 | 13 | 4 | 5/20 | **263** | **77** | 4 |
| 黑格尔 | 20 | 12 | 3 | 6/20 | **517** | **109** | 4 |
| 精神分析 | 20 | 10 | 3 | 4/20 | **162** | **55** | 4 |
| 拉康 | 20 | 13 | 3 | 4/20 | **267** | **77** | 4 |
| 辩证法 | 20 | 14 | 3 | 4/20 | **969** | **170** | 4 |

以「马克思」为例，语料中元数据命中该主题的块共 **263 个**，分布在 **77 个数值单元、4 个卷**。
点查询只取回 20 个候选、最终用 8 条证据成文（回答 895 字）；范围查询取回全部 263 块，
按单元聚合后输出 4270 字的结构化回答（离线后端），喂给 LLM 的上下文达 25 459 字。

与既有的专题提炼稿相比：

| 指标 | 专题提炼稿（全量人工） | 点查询 point（改造前） | 范围查询 theme（改造后） |
|---|---|---|---|
| 召回块数 | 443（关键词全量段） | 8–20 | 263–969 |
| 召回率（对相关块） | ≈100% | ≈2% | **100%（元数据命中）+ 语义补充** |
| 覆盖单元数 | 36（马克思稿） | 3–13 | **77–170** |
| 组织维度 | 单元 / 卷 / 谱系 / 批判 | 无（按分数散点） | **单元聚合 + 段落群** |
| 上下文规模 | 全量段落 | 7 787 字（用 895 字） | **25 459 字（用满）** |
| 单块信息利用率 | 100% | **29%** | ≈100% |
| 输出篇幅 | ≈15 000 字 | 895 字 | 4 270 字（离线）/ 可更长（LLM） |
| 谱系统计 | 有（上游/同代/后继/反对） | 无 | **有（共现频次）** |

## 三、差距的五个环节定位

### 环节 1｜检索与召回：`final_top_k = 8` 对 263–969 个相关块

**现状**：`retrieve.hybrid_search` 的 `final_top_k` 默认为 8，`answer.candidate_chunks` 为 20。
稠密 40 + 稀疏 40 → RRF 融合 → 取 top-8。

**后果**：召回率约 2%–8%。主题型问题需要的恰恰是「把该主题的所有相关块都取回」，
top-8 无论排序多准都必然截断。

**证据**：语料中「马克思」相关块 263 个，`ask` 只触达其中 20 个候选、8 个成文。
更严重的是，**取回的那 8 块并非主题最密集的块**——实测 top-8 命中单元为
`4-1-3-3 / 4-1-3-1 / 2-4-2-2 / 3-4-2 / 4-1-3-3 / 4-1-1-1 ×3`，
而真正的核心单元 `4-1-1-1`（20 块）、`4-1`（19 块）只命中 3 块。
`2-4-2-2`（涂尔干对照）和 `3-4-2`（阿尔都塞）属于语境提及，被排到了核心定义之前。

**根因**：检索按**单块相关性**排序，没有「主题覆盖度」这一目标；
`entity_boost = 0.004` 过弱，无法把「元数据命中主题」的块系统性提上来。

### 环节 2｜上下文组织：每块只取 1 句，信息利用率 29%

**现状**：`answer._topic_evidence` 对每个命中块只挑 **1 句**（`_sentence_score` 最高的那句），
最多 8 条，再按 `evidence_score` 排序取前 8，最后按 `seq` 还原原文顺序。

**后果**：
- **信息利用率 29%**（证据句平均 104 字 vs 块平均 319 字）。块的其余 70% 被丢弃。
- **论证链断裂**：8 条句子来自 8 个不同块，实测只有 4–6 条彼此相邻（seq 差 ≤3），
  跨卷乱跳是常态。
- **丢弃了结构信息**：`build_context` 只拼接 `c.text`，**不带章节路径、单元编号、单元标题**。
  生成器看到的是 8 段无出处的文字，自然无法按体系结构组织。

**根因**：`_topic_evidence` 是为「引用溯源」设计的——它要的是「最能回答这个问题的**那几句**」，
天然做减法；而主题提炼需要「该主题所在**整段**的完整论述」，需要做加法。

### 环节 3｜生成提示：长度约束差一个量级

**现状**：`answer.PROMPT_TEMPLATE` 要求
「分成 3—5 个自然段，依次说明：核心定义、形成机制或论证路径、不同理论位置的张力，最后给出一句总结；
**不超过 {max_chars} 字**」，其中 `max_answer_chars = 700`。

**后果**：即使检索召回足够，700 字也写不出专题提炼。对照既有专题稿：
马克思稿 379 行、约 15 000 字；黑格尔稿 205 行。**长度约束相差一个数量级。**

更关键的是提示词的**任务定义**：它说「为读者讲解」，是一个**问答任务**；
专题提炼需要的是「按体系结构分节展开」的**写作任务**。

### 环节 4｜后处理：完全没有聚合层

**现状**：`ask` 的产出是 `answer + citations[]`，其中 `citations` 是 8 个平铺的块。
`output.render_answer` 直接拼接。

**后果**：没有「按单元聚合」「谱系统计」「主题卡」这些环节。而 `facets` 接口其实
**已经统计了 unit / volume 维度**，但问答链路完全不消费它——两套能力彼此隔离。

### 环节 5｜词典（前置环节）：主题词未登录，元数据直接归零

**现状**：`lexicon/concepts.yaml` 收录 105 个概念，但**不含「精神分析」**这一主题词。

**后果**：对「精神分析」提问，元数据相关块数 = **0**。整条元数据通路失效，
只能靠向量近似兜底，主题集中度无从谈起。

**证据**：诊断脚本中「精神分析」的 `语料相关块总数 0`。
（同类缺口还有「德国观念论」「结构主义」等**流派/思潮级**词，词典只覆盖到「概念」和「理论家」两层。）

## 四、根因：点式检索与范围检索的架构错配

把上面五个环节合起来看，是一句话：

> **`ask` 是点查询（point query），专题提炼是范围查询（range query）。**
> 点查询优化「单条结果的精度」，范围查询优化「结果集的覆盖度与结构」。
> 两者的召回量、组织方式、上下文预算、输出形态都不同，不可能靠调参互相转换。

这也解释了为什么 `ask` 的评测指标很好看（Hit@1 = 96.43%、MRR = 0.9821）却答不好主题题：
**它测的就是「第一条命中的对不对」，而不是「该主题覆盖得全不全」。**

## 五、优化方案：把范围查询做成溯源回答的内部策略

**设计原则（v1.3 修正）：不新增入口。** `ask` 仍是唯一的问答入口，在问题闸门之后加一步
`classify_question` 判定提问类型，自动分派到点查询或范围查询；两条策略共用同一索引、
同一返回结构。用户输入「什么是字头」得到少而准的答案，输入「马克思在体系中的位置」
得到分节的结构化回答——**同一个版块，不同的召回策略**，不需要自己判断问题属于哪一类。

### 5.1 三层召回（对应旧方法的「全量关键词扫描」）

| 层级 | 判定 | 证据强度 | 对应旧方法 |
|---|---|---|---|
| `meta` | 词典归一后，块标签含该主题 | 最硬 | 显名层 + 概念层 |
| `literal` | 块正文直接出现主题词 | 次硬 | **全量关键词扫描**（`c.count('黑格尔')`）|
| `semantic` | 向量近似但未点名 | 最软 | 结构层（不点名但相关）|

召回量从 8 提升到「全部直接命中块」，实测马克思 263、黑格尔 517、辩证法 969。

**主题锚定**：主题词先经词典归一为 philosopher / concept / unit。
**未登录主题自动退化为种子模式**——先检索，再从种子块的高频共现元数据反推锚点。
实测「精神分析」（词典未收录）反推出锚定单元 `3-4-4-2`（经典的精神分析）、
`3-4-4-4`（针对资本主义的精神分析），**正是该主题的两个核心单元**。

### 5.2 单元聚合 + 段落群恢复（对应旧方法的「密度聚合 + 核心单元全文导出」）

- 直接命中块按**最细数值单元**分桶（`unit_code()`）；
- 桶内按块序把相邻块（seq 差 ≤ `group_gap`）合并为**段落群**，恢复被分块切碎的论证链；
- 按命中数排序，得到「主题密度分布」；密度 = 命中块数 / 该单元总块数。

实测马克思：`4-1-1-1` 20/31（密度 0.645）、`4-1` 19/44（0.432）、`4-1-3-1` 13/23（0.565）。
**这正是旧专题稿 §1.4 那张「马克思密度分布表」的自动版本。**

### 5.3 结构化上下文（修复环节 2）

不再「每块取 1 句」，而是：
- 每个单元取主题密度最高的**完整段落群**（上限 `max_group_chars = 1500`）；
- 上下文**带结构标题**：`### 单元 4-1-1-1 经济学哲学批判｜第 4 卷 实践｜命中 20 块`；
- 上下文预算从 7 787 字提升到 `context_budget = 24000` 字。

### 5.4 专题提示词（修复环节 3）

新增 `THEME_PROMPT`，与 `PROMPT_TEMPLATE` 并列：

- 任务从「讲解一个问题」改为「撰写一份主题专题提炼」；
- **固定四节**：① 体系定位 ② 核心单元的思想骨架 ③ 衍生与谱系 ④ 张力与批判
  ——直接对应既有专题稿的「原点—扩散—反冲」三段结构；
- 明确要求「每个核心单元至少 2—3 句，**不要只摘一句就换下一个单元**」；
- 长度 1500—4000 字（`theme_min_chars` / `theme_max_chars`）。

### 5.5 谱系与后处理（修复环节 4）

- 统计直接命中块中与主题**共现的理论家频次** → 谱系线索。
  实测马克思：黑格尔 66、列宁 40、谢林 30、恩格斯 30、阿尔都塞 29、卢卡奇 27；
  拉康：黑格尔 49、齐泽克 39、巴迪欧 29、康德 26、阿尔都塞 26 —— **正是各稿 §4「谱系」一节的内容**；
- 统计年代分布；
- 离线后端按单元分节输出「专题正文」，每节含主题句群 + 关键引文。

### 5.6 词典补主题层（修复环节 5）

建议在 `lexicon/` 下新增 `themes.yaml`（流派/思潮级主题词：精神分析、德国观念论、
结构主义、后结构主义、存在主义、法兰克福学派…），归一到 `concepts` 与 `units`。
当前已用「种子模式」兜底，但显式主题表能进一步提高未登录主题的锚定精度。

## 七、剩余差距与后续优化

改造后仍与人工专题稿有差距，按性价比排序：

1. **离线模板后端 vs LLM 后端**。`backend: template` 输出的是「分节的证据群」，
   有结构但无连贯论述；`api` / `ollama` 后端才能得到成篇散文。
   生成层现已默认 `api`（阿里云百炼 DashScope，OpenAI 兼容），只需在 `.env` 填 key
   即可获得连贯的成篇论述——这是**当前最大的剩余差距**，且只需一把 key。
2. **谱系的「方向性」**。当前只统计共现频次，无法区分上游 / 同代 / 后继 / 反对。
   可用生卒年（`lexicon` 已有 `birth`）做粗排序，精确关系仍需 LLM 或规则表。
3. **主题层的词典缺口**（见 5.6）。「精神分析」这类词目前靠种子模式兜底，显式主题表更稳。
4. **单元间关系的显式建模**。旧稿会做「3-4-4-4 与 4-1-1-1 两处关于《资本论》的论述作专门对照」
   （见马克思稿整理者按），这需要跨单元的同主题对齐，当前只做到「分单元呈现」。
5. **评测集需要扩充主题型问题**。现有 28 条标注全是点式问题，
   **无法衡量专题链路的质量**——建议补一套「主题覆盖度」标注（该主题应覆盖哪些单元）。

## 附：为什么 `ask` 的指标这么好却答不好主题题

`eval` 的 28 条标注问的是「必须命中的关键词」，衡量的是**单条命中的准确性**。
`ask` 的 Hit@1 = 96.43% 说明它**定位准**——这对「引用溯源」是核心能力，不应改动。

问题在于：**没有一条指标衡量「覆盖度」**。于是链路可以一路优化到 Hit@1 96%，
而主题集中度始终是 8 条散点。这也是本次诊断最有价值的发现：
**指标设计决定了系统会往哪个方向优化，而主题提炼从一开始就不在指标里。**
